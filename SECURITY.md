# Security Policy & Enforced Invariants

EdgeGate is designed as a high-assurance L7 security choke point between untrusted workloads (AI agents, ephemeral sandboxes, multi-tenant containers) and external or internal HTTP/HTTPS services.

## Reporting a Vulnerability

- **Do not open public GitHub issues for suspected security vulnerabilities.**
- Please report vulnerabilities privately via [GitHub Security Advisories](https://github.com/creova-gif/edgegate/security/advisories/new) for `creova-gif/edgegate`.
- Include a minimal reproduction config (`edgegate.toml`), request payload/headers, and expected vs. observed behavior.

---

## Enforced Security Invariants

Every request processed by EdgeGate is subject to the following non-negotiable security invariants, verified continuously by unit, integration, and adversarial test suites:

| Invariant ID | Security Property | Implementation Mechanism | Enforcing Module |
|---|---|---|---|
| **INV-01** | **Fail-Closed Pre-Policy Path Normalization** | Rejects paths not starting with `/`, double slashes (`//`), raw or percent-encoded dot-segments (`.`, `..`, `%2e`, `%2e%2e`, `.%2e`, `%2e.`), backslashes (`\`, `%5c`), encoded slashes (`%2f`), null bytes (`%00`), and ASCII control characters (`< 0x20`, `0x7f`) with `400 Bad Request` **before** route matching or policy evaluation. | [`src/router.rs`](src/router.rs) (`validate_request_path`) |
| **INV-02** | **Constant-Time Token Verification & Dual-Token Rollover** | Pre-computes SHA-256 digests of primary (`token` / `token_sha256`) and rollover (`secondary_token` / `secondary_token_sha256`) workload tokens at config compilation and compares candidate digests using `subtle::ConstantTimeEq` (`ct_eq`) to prevent character-by-character timing side channels while enabling zero-downtime key rotation. | [`src/auth.rs`](src/auth.rs) (`HeaderTokenAuthenticator`) |
| **INV-03** | **Zero-Token Transport-Bound Identity** | Dedicated per-sandbox Unix domain sockets (`[[server.unix_listeners]]` and `EdgeGateProxy::register_boxlet_sandbox`) bind workload identity (`workload_id`, `org_id`, `roles`) directly to the OS socket boundary, requiring zero bearer tokens inside the sandbox. | [`src/auth.rs`](src/auth.rs), [`src/proxy.rs`](src/proxy.rs) |
| **INV-04** | **Default-Deny Multi-Tenant & RBAC Policy** | Denies all requests unless an explicit policy rule matches `(org_id, workload_id, required_roles, route_id, method, path_prefix, required_headers)` using segment-boundary-safe prefix matching (`/v1/repos` never matches `/v1/repos-admin`). | [`src/policy.rs`](src/policy.rs) (`DefaultDenyPolicyEngine`) |
| **INV-05** | **Cross-Tenant Credential Isolation & Zeroization** | Scopes every secret lookup to `(identity.org_id, binding.credential_ref)`. Wraps secret bytes in `SecretValue` (`zeroize::ZeroizeOnDrop`) with `Debug` and `Display` unconditionally redacted to `"[REDACTED]"`. | [`src/secrets.rs`](src/secrets.rs) (`SecretValue`, `MockSecretProvider`) |
| **INV-06** | **Outbound Header Smuggling & Credential Override Prevention** | Unconditionally strips `X-EdgeGate-Token`, `Proxy-Authorization`, all RFC 9110 hop-by-hop headers, any header names dynamically listed in incoming `Connection` headers (except `content-length` and `transfer-encoding`), and the route's target credential header before injecting the upstream secret; rewrites `Host` to the backend's configured authority. | [`src/router.rs`](src/router.rs) (`sanitize_outbound_headers`) |
| **INV-07** | **Resolve-Validate-Connect SSRF Defense** | Resolves DNS once, validates all returned IPv4, IPv6, and unwrapped IPv4-mapped IPv6 (`::ffff:169.254.169.254`, `::ffff:127.0.0.1`) addresses against the private/loopback/link-local/metadata/CGNAT/ULA blocklist (unless `allow_private_ip = true` for local test fixtures), and connects directly to the validated `SocketAddr` to eliminate DNS-rebinding TOCTOU. | [`src/pool.rs`](src/pool.rs) (`resolve_and_validate_addr`, `is_blocked_ip`) |
| **INV-08** | **Zero Redirect Following (`3xx` Credential Leak Prevention)** | Never follows `301`/`302`/`307`/`308` upstream redirects; returns `3xx` responses directly to the caller so an injected upstream credential is never forwarded to a redirect target. | [`src/proxy.rs`](src/proxy.rs), [`src/pool.rs`](src/pool.rs) |
| **INV-09** | **HTTP/1.1 Stream Isolation (`PooledBody` Guard)** | Returns an HTTP/1.1 `SendRequest` handle to the idle pool **only** after the response body reaches clean EOF, `!Connection: close`, `!sender.is_closed()`, and `sender.is_ready()`. Early client disconnect or body error immediately drops the connection. | [`src/pool.rs`](src/pool.rs) (`PooledBody`) |
| **INV-10** | **Bounded Request Payloads & Concurrency** | Enforces `max_request_body_bytes` via `http_body_util::Limited` (`413 Payload Too Large`), per-workload token-bucket rate limits (`429 Too Many Requests`), and per-backend `Semaphore` concurrency caps (`503 Service Unavailable`). | [`src/proxy.rs`](src/proxy.rs), [`src/pool.rs`](src/pool.rs) |
| **INV-11** | **Secret-Free Structured Audit Logs & Flight Recorder** | Audit logs (`edgegate::audit`) and the `/_edgegate/replay` ring buffer record only sanitized routing, identity, timing, and status metadata—never request/response headers, bodies, or credentials. | [`src/telemetry.rs`](src/telemetry.rs) (`Telemetry`, `ReplayRecord`) |
| **INV-12** | **Response Credential Reflection Guard** | When `block_secret_reflection = true` is configured on `[routes.credential]`, EdgeGate inspects upstream response headers, buffered response body bytes, and HTTP/2 response trailers for the injected secret and fails closed with `502 Bad Gateway` (`secret_reflections_blocked_total` + sanitized `/_edgegate/replay` entry) if a misconfigured or malicious upstream reflects the credential. | [`src/proxy.rs`](src/proxy.rs), [`src/telemetry.rs`](src/telemetry.rs) |
| **INV-13** | **Idempotent-Only Retry Safety** | When `max_idempotent_retries > 0` is configured on `[[pools]]`, EdgeGate retries connect/transport failures **exclusively** for safe HTTP methods (`GET`, `HEAD`, `OPTIONS`) against the next healthy backend and **never** retries state-mutating methods (`POST`, `PUT`, `PATCH`, `DELETE`). | [`src/proxy.rs`](src/proxy.rs), [`src/config.rs`](src/config.rs) |
| **INV-14** | **Scoped Credential Rotation & Fail-Closed TTL Expiry** | Enforces optional `expires_at_epoch_s` TTL deadlines on `[[secrets]]`, failing closed with `403 Forbidden` the instant a credential expires, and supports live in-memory atomic secret rotation via `EdgeGateProxy::rotate_secret` and `/_edgegate/admin/secrets/rotate` (`secret_rotations_total`) with automatic zeroization of superseded secret values. | [`src/secrets.rs`](src/secrets.rs), [`src/proxy.rs`](src/proxy.rs) |
| **INV-15** | **Programmable Request-Attribute Policy Matching** | Enforces optional `required_headers` exact header/attribute predicates on `[[policies]]` (e.g., `required_headers = { "x-mcp-tool" = "github.read_repo" }` for Keelway MCP Gateway and IoRa tool-call governance), rejecting requests with missing or mismatched attribute values with `403 Forbidden` before any upstream connection or credential lookup occurs. | [`src/policy.rs`](src/policy.rs), [`src/config.rs`](src/config.rs) |
| **INV-16** | **Cryptographic SHA-256 Hash-Chained Tamper-Evident Audit Ledger** | Chains every gateway decision into a SHA-256 hash ledger (`prev_hash` -> `entry_hash` over `request_id`, `trace_id`, `org_id`, `workload_id`, `route`, `upstream`, `decision`, `status`, and `latency_us`), verified on demand via `/_edgegate/admin/audit` (gated by constant-time `X-EdgeGate-Admin-Token` via `server.admin_token` / `server.admin_token_sha256`, disabled fail-closed when unconfigured) and continuously exported via `audit_chain_valid` in `/_edgegate/metrics`. | [`src/telemetry.rs`](src/telemetry.rs), [`src/proxy.rs`](src/proxy.rs) |
| **INV-17** | **Per-Rule Query-Parameter & Payload Resource Limits** | Enforces `forbidden_query_params` on `[[policies]]` to block disallowed query parameters with `403 Forbidden` before upstream dispatch, and enforces per-rule `max_body_bytes` request payload ceilings via `http_body_util::Limited` (`413 Payload Too Large`). | [`src/policy.rs`](src/policy.rs), [`src/proxy.rs`](src/proxy.rs), [`src/config.rs`](src/config.rs) |
| **INV-18** | **Outbound Mutual TLS (mTLS) Client Authentication** | Compiles and validates pool-scoped `client_cert_pem` + `client_key_pem` pairs via `rustls` / `rustls-pemfile` at configuration load/hot-reload time (failing closed on partial or mismatched key material) and presents the X.509 client certificate during upstream TLS 1.2/1.3 handshakes without ever exposing private key material to workloads. | [`src/config.rs`](src/config.rs), [`src/pool.rs`](src/pool.rs) |
| **INV-19** | **Egress Data Loss Prevention (DLP) Request Payload Guard** | Scans bounded outbound request payloads against per-rule `blocked_body_substrings` before any upstream socket checkout or secret transmission, rejecting exfiltration attempts fail-closed with `403 Forbidden`, incrementing `dlp_blocked_total` (`edgegate_dlp_blocked_total`), and recording sanitized `dlp_payload_blocked` flight-recorder entries. | [`src/policy.rs`](src/policy.rs), [`src/proxy.rs`](src/proxy.rs), [`src/telemetry.rs`](src/telemetry.rs) |
| **INV-20** | **Stream-Lifetime Workload Concurrency Quotas & Bulkhead Isolation** | Enforces semaphore-backed per-`(org_id, workload_id)` in-flight concurrency caps on both token-authenticated TCP workloads and zero-token Unix domain socket listeners (`max_concurrent_requests`). Rejects requests exceeding concurrency limits fail-closed with `429 Too Many Requests`, `Retry-After: 1`, and increments `edgegate_bulkhead_rejected_total`. Active counters (`Arc<AtomicUsize>`) and lookups operate wait-free via `ArcSwap` across live hot reloads, eliminating lock contention, and `GuardedResponseBody` retains bulkhead and drain guards across streaming response lifetimes (SSE, gRPC, chunked HTTP) until stream EOF or client drop. | [`src/auth.rs`](src/auth.rs), [`src/proxy.rs`](src/proxy.rs), [`src/config.rs`](src/config.rs) |
| **INV-21** | **Per-Route Timeout SLAs, Trailer-Preserving Body Ceilings & Breaker Fault Isolation** | Enforces route-granular upstream response timeout deadlines (`timeout_ms`, overriding server `response_timeout_ms` with `504 Gateway Timeout`) and enforces strict upper bounds on upstream response body sizes (`max_response_body_bytes`). Terminates responses exceeding the limit with `502 Bad Gateway` while preserving HTTP/2 trailers (`BufferedBodyWithTrailers`) and isolating `http_body_util::LengthLimitError` from tripping shared backend circuit breakers. | [`src/proxy.rs`](src/proxy.rs), [`src/pool.rs`](src/pool.rs), [`src/lb.rs`](src/lb.rs), [`src/config.rs`](src/config.rs) |
| **INV-22** | **Strict JSON-RPC 2.0 / MCP Method Allowlists & HTTP/2 Trailer Scrubbing** | Enforces RFC 8259 `serde_json` parsing on incoming JSON-RPC 2.0 requests when `allowed_jsonrpc_methods` is configured on `[[policies]]`. Mandates `"jsonrpc": "2.0"` on all single and batch objects, treats `allowed_jsonrpc_methods = []` as an explicit fail-closed deny-all (`403 Forbidden`), and rejects disallowed methods, invalid JSON, or batch smuggling with `403 Forbidden` (`edgegate_jsonrpc_blocked_total`). Unconditionally applies route `strip_response_headers` to both HTTP/2 response headers and response trailers. | [`src/policy.rs`](src/policy.rs), [`src/proxy.rs`](src/proxy.rs), [`src/config.rs`](src/config.rs) |
| **INV-23** | **Outbound Cryptographic Request Signing & Forged Signature Stripping** | Injects RFC 2104 compliant HMAC-SHA256 signatures (`X-EdgeGate-Signature-256: sha256=<hex>`, `X-EdgeGate-Timestamp: <unix_epoch_s>`) computed over `<timestamp>.<raw_body>` on routes configured with `[routes.request_signing]`. Backed by org-scoped `SecretProvider` with fail-closed TTL enforcement (`INV-14`), with incoming caller-forged signature and timestamp headers unconditionally stripped in `sanitize_outbound_headers` prior to signing (`edgegate_signed_requests_total`). | [`src/router.rs`](src/router.rs), [`src/proxy.rs`](src/proxy.rs), [`src/config.rs`](src/config.rs), [`src/telemetry.rs`](src/telemetry.rs) |
| **INV-24** | **Inbound Mutual TLS (mTLS) Client Verification** | Enforces X.509 client certificate authentication on inbound TLS listener connections when `client_ca_cert_pem` or `client_ca_cert_path` is configured in `[server.tls]` via `rustls::server::WebPkiClientVerifier`. Unauthenticated TLS handshakes or client certificates not signed by the trusted client CA fail at the TLS layer before any HTTP framing bytes are accepted. | [`src/config.rs`](src/config.rs), [`src/proxy.rs`](src/proxy.rs) |
| **INV-25** | **Outbound AWS Signature Version 4 (SigV4) Request Signing** | Computes canonical AWS SigV4 signatures (`AWS4-HMAC-SHA256`, `x-amz-date`, `x-amz-content-sha256`) on outbound requests matching routes configured with `[routes.aws_sigv4]` for S3, Bedrock, DynamoDB, R2, and MinIO backends. Backed by org-scoped AWS access/secret keys with fail-closed TTL enforcement (`INV-14`), automatic stripping of caller-forged `Authorization` and `x-amz-*` headers, and compile-time validation preventing collision with `[routes.credential]` or `[routes.request_signing]`. | [`src/router.rs`](src/router.rs), [`src/proxy.rs`](src/proxy.rs), [`src/config.rs`](src/config.rs), [`src/telemetry.rs`](src/telemetry.rs) |
| **INV-26** | **Embedded WCAG 2.1 AA+ Operator Control-Plane Web Console** | Serves an embedded, zero-dependency, self-contained operator console at `GET /_edgegate/console` featuring an adaptive dark/light high-contrast design system (`prefers-color-scheme`, `prefers-reduced-motion`), keyboard skip-links, WAI-ARIA landmarks & `aria-live` announcements, strict `Content-Security-Policy` (`default-src 'none'`, `frame-ancestors 'none'`), and memory-only admin token handling without disk or local storage leakage. | [`src/console.rs`](src/console.rs), [`src/proxy.rs`](src/proxy.rs) |
| **INV-27** | **Route-Level CORS Preflight & Browser/MCP Interoperability** | Enforces route-level CORS governance via `[routes.cors]`. Forbids insecure wildcard origins (`*`) when credentials or specific origins are required, validates incoming `Origin` headers against strict allowlists, short-circuits `OPTIONS` preflight requests with `204 No Content` and zero secret exposure or upstream connection checkout, and sets `Vary: Origin` and `Access-Control-Expose-Headers` defensively. | [`src/router.rs`](src/router.rs), [`src/proxy.rs`](src/proxy.rs), [`src/config.rs`](src/config.rs) |

## Residual Risks & Explicit Non-Goals

1. **Obfuscated or Compressed Upstream Credential Reflection:**
   When `block_secret_reflection = true` (`INV-12`) is enabled on `[routes.credential]`, EdgeGate blocks verbatim reflection of the injected secret in upstream response headers and bodies (`502 Bad Gateway`). However, if a deliberately malicious upstream encodes, encrypts, or compresses the echoed credential before returning it, byte-pattern scrubbing cannot guarantee confidentiality against arbitrary steganography. Operators should only bind scoped credentials to trusted upstream authorities.
2. **Kernel / Container Escape Outside Network Namespace:**
   EdgeGate enforces network and L7 protocol boundaries. Host kernel isolation, seccomp filters, and container/VM sandboxing (`internal: true` Docker networks, Boxlet microVMs, mount namespaces) are the responsibility of the container runtime or hypervisor.
3. **Denial-of-Service Against Shared Upstream Quotas:**
   While EdgeGate enforces per-workload rate limits (`rate_limit_rps` / `rate_limit_burst`), request body size caps (`max_request_body_bytes`), and per-backend connection pool semaphores (`max_connections_per_upstream`), authorized workloads within their configured rate limits still consume upstream API quota.

## Adversarial Verification Commands

Run the full automated security and adversarial verification suite locally:

```bash
# 1. Run all unit, integration, and adversarial security tests (path traversal, SSRF,
#    header smuggling, cross-tenant isolation, 3xx redirect non-follow, dirty body drop,
#    TLS verification, UDS zero-token auth, circuit breakers, rate limiting, credential TTL expiry,
#    live secret rotation, dual-token rollover, and required_headers MCP attribute policies)
cargo test --all-targets

# 2. Run the interactive 5-scenario zero-secret security console demo
cargo run --example security_console_demo

# 3. Enforce strict static analysis (zero warnings, zero .unwrap()/.expect() in production code)
cargo clippy --all-targets -- -D warnings

# 4. Run the end-to-end Docker zero-bypass container proof
#    Proves that an isolated sandbox container with zero API keys and no default route
#    cannot reach the internet or upstream directly, yet succeeds through EdgeGate's policy engine
docker compose -f docker-compose.demo.yml up -d --build
./scripts/demo-verify.sh
docker compose -f docker-compose.demo.yml down
```
